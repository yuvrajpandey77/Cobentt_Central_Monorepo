  ```5:22:src/lib/sandbox-utils.ts
  export const SANDBOX_TIMEOUT_MS = 60_000 * 10 * 2; // 20 minutes
  export const SANDBOX_WARNING_THRESHOLD_MS = 60_000 * 18; // 18 minutes

  export function shouldAutoRestoreSandbox(fragment: { createdAt: Date; sandboxUrl?: string | null }): boolean {
      if (!fragment.sandboxUrl) return true;
      const now = new Date();
      const createdAt = new Date(fragment.createdAt);
      const ageMs = now.getTime() - createdAt.getTime();
      return ageMs > SANDBOX_WARNING_THRESHOLD_MS;
  }
  ```

### How we implemented it
- UI actions use `AsyncButton` with toast-driven feedback and Suspense fallbacks to avoid blocking the main thread and maintain responsiveness.
- Sandbox lifecycle helpers are pure utilities with time-based thresholds to keep `ProjectView` lean.
- The download API performs a single read of all fragments, groups files by fragment when necessary, zips in-memory, and streams back with appropriate headers.
- Schema changes are additive and backward-compatible; migrations should be applied before deploying the API/UI features.

### Risks and mitigations
- Large projects may generate big ZIPs in memory.
  - Mitigation: consider streaming zip generation or server-side temp files; enforce size caps.
- Stale `createdAt` as a proxy for sandbox lifetime may be imperfect.
  - Mitigation: store sandbox heartbeat or expiry timestamp per fragment.
- Gradient text could reduce readability in certain themes.
  - Mitigation: apply `.no-text-gradient` on critical/interactive text when needed.
